# Ajax Email Signature

Статичний веб-застосунок для генерації email-підпису співробітників Ajax Systems (Gmail, Outlook).

**Онлайн:** https://denysrastokin.github.io/ajax-email-signature/

Дані, які вводить співробітник, нікуди не відправляються: підпис збирається в браузері,
а заповнені поля зберігаються лише локально (localStorage), щоб не вводити їх повторно.

## Файли

- `index.html`, `styles.css`, `app.js` — застосунок (без збірки й залежностей).
- `assets/ajax-banner.jpg` — банер з нагородами (840×219, показується як 420 px — чіткий на Retina).
- `assets/youtube.png` — іконка YouTube (40×28, показується як 20×14).
- `assets/ajax-logo.svg`, `assets/favicon-*.png`, `assets/apple-touch-icon.png` — логотип і favicon з ajax.systems (лише для сторінки редактора).

## Розміщення

Зараз застосунок розміщено на GitHub Pages (гілка `main`, коренева папка): кожен push у `main` оновлює сайт за 1–2 хвилини.

Зображення в підписі підвантажуються поштовими клієнтами за **публічним URL**, тому застосунок
(або хоча б папку `assets/`) треба розмістити на публічному HTTPS-хостингу: GitHub Pages, Netlify,
корпоративний CDN тощо.

- Якщо `assets/` лежить поруч з застосунком — нічого налаштовувати не треба.
- Якщо зображення на іншому домені — вкажіть адресу в `ASSET_BASE_URL` на початку `app.js`.

Не переміщуйте й не перейменовуйте файли після того, як співробітники встановили підписи,
інакше зображення в них зламаються.

## Дизайни підпису

Угорі форми — вибір дизайну (за замовчуванням `DEFAULT_DESIGN = 'classic'`):

- **Classic** — фото 90×90 зі скругленням ліворуч, ім'я, «Посада | Ajax Systems», рядки Mobile / Email, іконки й кнопка під контактами.
- **Modern** — кругле фото 56×56 поруч з іменем (без фото — лише текст), під іменем посада сірим,
  контакти колонками з підписами MOBILE / EMAIL (на вузьких екранах колонки переносяться одна під одну),
  іконки соцмереж і кнопка «Book a meeting» на світло-сірій плашці. Параметри — константа `MODERN` в `app.js`.

Обидва дизайни мають лінію зверху й однаковий промо-блок унизу.

## Фото

Фото необов'язкове й додається **посиланням** на вже розміщене зображення (поле «Photo URL»).
У підписі воно стоїть ліворуч від контактів, розміром 90×90 (стільки ж займають ім'я 19px і 3 рядки тексту) і зі скругленням 16px.

- Вимоги: квадрат від 180×180 px (для Retina), публічне посилання `https://`, що веде прямо на файл зображення.
  Посилання на сторінки перегляду Google Drive / OneDrive / SharePoint не підійдуть.
- Застосунок попереджає, якщо посилання не https, картинка не вантажиться, не квадратна або замала.
- Класичний Outlook для Windows не підтримує `border-radius`, тому там кути фото будуть прямі.
- Далі: замінити поле на завантаження файлу в хостинг (Cloudinary або CDN Ajax) з кадруванням (масштаб і зсув).
  Параметри фото задані в константі `PHOTO` у `app.js`.

## Посилання на підпис

Кнопка «Copy signature link» копіює адресу сторінки, у якій усі заповнені поля передані параметрами URL, наприклад
`…/?name=John+Smith&title=Marketing+Manager&email=smith.j&telegram=%40johnsmith`. Хто відкриє посилання, побачить форму,
заповнену цими даними (вони мають пріоритет над збереженими в браузері). Після відкриття параметри прибираються з адресного рядка.

Параметри: `design=modern`, `name`, `title`, `mobile`, `email` (лише частина до `@`), `photo`, `linkedin`, `telegram`, `whatsapp`,
`meeting`, `wa=mobile` (WhatsApp як мобільний), `ms=icon` (зустріч іконкою замість кнопки), `promo` (`id` з `PROMO_LINKS` або `none`), `lang=uk`.
Порожні поля й значення за замовчуванням у посилання не потрапляють.

Посилання містить контактні дані людини у відкритому вигляді, тож надсилайте його лише тим, кому вони призначені.

## Соцмережі та месенджери

Необов'язковий блок «Add social networks & messengers» у формі (згорнутий за замовчуванням, відкривається сам,
якщо поля вже заповнені). Заповнені поля показуються в підписі рядком круглих монохромних іконок 22px під контактами.

- **LinkedIn:** будь-яке посилання на профіль (`linkedin.com/in/…`, з `https://` чи без, регіональні піддомени) →
  `https://www.linkedin.com/in/…`.
- **Telegram:** `@username`, `username` або `t.me/username` → `https://t.me/username`.
- **WhatsApp:** номер у міжнародному форматі з `+` → `https://wa.me/<цифри>`; галочка «Same as mobile» бере мобільний номер.
- Нерозпізнані значення в підпис не потрапляють, під полем з'являється підказка.
- **Запис на зустріч:** посилання Calendly, Google Calendar (сторінки запису), Outlook Bookings, HubSpot Meetings або
  будь-яке інше `https://` (для невідомих сервісів — м'яке попередження). Два варіанти вигляду:
  чорна кнопка-«пігулка» «Book a meeting» на початку рядка (текстом, без картинки; у класичному Outlook кути прямі)
  або іконка календаря `assets/calendar.png` в кінці рядка іконок.
- Іконки: `assets/linkedin.png`, `assets/telegram.png`, `assets/whatsapp.png` (44×44, показуються як 22×22).

## Промо-блок («Promo block»)

Внизу підпису показується один промо-блок, вибраний у випадаючому списку, або жодного («— No promo —»).
Варіанти задаються в масиві `PROMO_LINKS` на початку `app.js`; значення за замовчуванням — `DEFAULT_PROMO`.
Кожен варіант має `id`, назву для списку (`label.en` / `label.uk`), `url` і тип:

- `type: 'link'` — текстове посилання (`text`) з іконкою (`icon`: файл у `assets/` подвійного розміру, напр. 40×28 для показу 20×14);
- `type: 'banner'` — картинка на всю ширину підпису (`image`: файл у `assets/` шириною 2× від `width`, напр. 840 px для 420).

Зараз доступні: посилання на YouTube-канал Ajax PRO і банер Ajax з нагородами.

## Локальний запуск

```bash
npx http-server . -p 5510
```

## Особливості верстки підпису

- Таблична верстка та лише inline-стилі: Gmail вирізає `<style>`, Outlook для Windows рендерить через Word.
- Банер: атрибут `width="420"` для Outlook + `width:100%; max-width:420px; height:auto` для адаптиву на телефонах.
- Шрифт `Roboto, Arial, Helvetica, sans-serif`, `mso-line-height-rule:exactly` для стабільних інтервалів в Outlook.
- Телефон і email — явні `tel:`/`mailto:` посилання зі стилем, щоб iOS/Gmail не перефарбовували їх у синій.
- У всіх зображень є `alt`, тож підпис читається навіть з вимкненими картинками.

## Безпека

- Усе, що вводить користувач (у тому числі з посилання з параметрами), екранується перед вставкою в HTML підпису;
  посилання будуються лише з дозволених схем: `https://` (фото, LinkedIn, Telegram, WhatsApp), `tel:`, `mailto:`.
- Content Security Policy (`<meta>` в `index.html`): скрипти лише з власного домену, без `eval` та inline-скриптів;
  картинки — з власного домену або `https:` (для фото за посиланням).
- `referrer`: `no-referrer` — сторонні сервери з фото не бачать адресу сторінки.
- Сервера та зовнішніх скриптів немає; дані не залишають браузер, окрім завантаження фото за вказаним посиланням.
- Якщо форму відкрито з посилання з даними, показується попередження перевірити їх перед копіюванням.
